# D03 — Fix classic checkout first; block checkout ships as a separate change

- Date, owner: 2026-09-22, Mateusz Zadorożny (maintainer)
- Context and the options weighed: during this session the non-breaking-space problem was found to affect block checkout too. WooCommerce 10.9.4 `src/StoreApi/Schemas/V1/AbstractAddressSchema.php:237-239` runs `wc_remove_non_displayable_chars()` and then the same `WC_Validation::is_phone()`; the strip list in `includes/wc-formatting-functions.php:1657-1677` covers fifteen formatting characters and does not include U+00A0, U+202F or U+2007. That rejection happens before `woocommerce_store_api_checkout_update_order_from_request`, the hook `src/Checkout/BlockCheckoutValidator.php:67` registers. The fix described in issue #23 uses `woocommerce_process_checkout_field_{billing,shipping}_phone`, a `WC_Checkout::get_posted_data()` hook that never fires on the Store API path. Three options were put to the maintainer: cover both paths in one change; ship classic first and treat block separately; or look for a single entry point serving both before scoping anything.
- Decision and why: ship the classic-checkout fix now and handle block checkout as a separate tracked change. Chosen by the maintainer for a smaller first change.
- Consequences, and what would make us revisit it: between the two changes, rule R02 — classic and block checkout must reach the same verdict on the same input — is knowingly not met for this input class. That gap is accepted deliberately, not overlooked, and needs its own tracker issue so it is not lost. Revisit if the interval grows or if the Store API case is reported from a live store first.
- Status: active
