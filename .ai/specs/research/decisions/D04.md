# D04 — A cleaned phone value may be stored even on fields the plugin skips

- Date, owner: 2026-09-22, Mateusz Zadorożny (maintainer)
- Context and the options weighed: the cleanup in D01 runs on `woocommerce_process_checkout_field_{billing,shipping}_phone`, which fires while WooCommerce assembles posted data — before `Checkout\Hooks::should_validate()` and before `Settings::is_format_on_save_enabled()` are consulted. A field a site deliberately skips would therefore no longer store exactly the characters the customer typed; whitespace would already be collapsed and trimmed. That contradicts the promise in the `should_validate` docblock at `src/Checkout/Hooks.php:31-33` — "Skipped fields are stored exactly as entered" — and touches `BACKWARD_COMPATIBILITY.md` §3 (Order data). The alternative weighed was cleaning only for the purpose of validation and restoring the original characters for storage whenever the plugin skips the field or `format_on_save` is off.
- Decision and why: accept the collapsed stored value. Chosen by the maintainer over preserving the original, for the simpler implementation.
- Consequences, and what would make us revisit it: the `should_validate` docblock and `BACKWARD_COMPATIBILITY.md` §3 must be corrected in the same pull request that ships the cleanup, because the current wording becomes false. Only whitespace is affected — separators, `00` → `+` and output formatting stay owned by `Validation\Normalizer` and the `output_format` setting. Revisit if a site reports that it depended on the exact stored characters of a skipped field.
- Status: active
