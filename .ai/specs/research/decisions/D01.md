# D01 — Input cleanup that would otherwise live in a theme belongs in the plugin

- Date, owner: 2026-09-22, Mateusz Zadorożny (maintainer)
- Context and the options weighed: issue #23 documents a phone number containing a non-breaking space being rejected by `WC_Validation::is_phone()` inside `WC_Checkout::validate_posted_data()`, which runs before `woocommerce_after_checkout_validation` where this plugin validates. A theme-side workaround (two `add_filter()` calls on `woocommerce_process_checkout_field_{billing,shipping}_phone`) already fixes it on the affected install. The options were: keep fixing it per theme, or move the cleanup into the plugin so every classic-checkout installation gets it.
- Decision and why: the plugin owns it. Asked what this session should decide, the maintainer answered "so as not to build an extra workaround in the future". The reasoning recorded in issue #23 is that every classic-checkout install hits this, so a per-theme fix multiplies the same work.
- Consequences, and what would make us revisit it: the plugin takes on a hook that runs earlier than its current validation entry point, widening the surface it touches on classic checkout. It does not change what counts as a valid number — only which characters survive to be parsed. Revisit if WooCommerce core fixes `WC_Validation::is_phone()` upstream, which would make the plugin-side filter redundant.
- Status: active
